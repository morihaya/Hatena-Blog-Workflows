検証で利用していたAWS Workspacesのお掃除をしていたところ、以下のエラーが発生して消せなくて焦りました。


> An Error Has Occurred
Cannot delete the directory because it still has authorized applications. Additional directory details can be viewed at the Directory Service console.

<figure class="figure-image figure-image-fotolife" title="エラー画面">[f:id:morihaya:20200403171821p:plain]<figcaption>エラー画面</figcaption></figure>

## 対策: 利用中のアプリを先に削除する

原因は全てのアプリを削除していないためでした。エラーメッセージのリンク先に飛ぶと、ディレクトリの詳細ページが表示され、以下のように利用中のアプリケーションの一覧んを確認できます。

この図では `Amazon WorkDocs` が `Enabled` になっているため、ディレクトリを削除できなかったのです。
 
<figure class="figure-image figure-image-fotolife" title="利用中のアプリ一覧">[f:id:morihaya:20200403172317p:plain]<figcaption>利用中のアプリ一覧</figcaption></figure>

リンク先へ飛びWork Docsも削除します。WorkDocsの削除画面には親切なことに `I also want to delete the user directory` オプションが表示されましたので、チェックを入れて削除を行います。

<figure class="figure-image figure-image-fotolife" title="WorkDocs削除画面">[f:id:morihaya:20200403172624p:plain]<figcaption>WorkDocs削除画面</figcaption></figure>

念のため Workspacesのディレクトリ一覧に戻ると、 `deleting` ステータスを確認できました。こちらでお掃除が完了です。
<figure class="figure-image figure-image-fotolife" title="削除されつつあるディレクトリの図">[f:id:morihaya:20200403172949p:plain]<figcaption>削除されつつあるディレクトリの図</figcaption></figure>


まとめ。

GUIでサクサクと起動できるのはいいですが、裏で複数サービスが連携して作成されることで、一箇所で削除ができないのはよくある話ですが、直面すると少し焦りますね。
