AWS Lambdaはちょっとした内部用のツール程度にしか使ってこなかったため、デプロイ方法やコードの管理をちゃんと考えてきていませんでした。
今後それではまずそうなので、何がいいのか適当に調べてみます。


ざっと調べるだけで以下の候補がでてきました。

- [AWS Serverless Application Model (AWS SAM)](https://github.com/aws/serverless-application-model)
- [The Serverless Framework](https://github.com/serverless/serverless)
- [HashiCorp Waypoint](https://github.com/hashicorp/waypoint)
- [apex/up]()


## AWS Serverless Application Model (AWS SAM)

AWSに特化するならこれなのでは。
Black Belt や、公式のドキュメントとして利用方法が紹介されており、AWSリソースを中身として使うならこれがよさそうという印象。


## The Serverless Framework

とにかく多くのプラットフォームに対応しており、かつ歴史もある。
ただし、多くをカバーするが故にAWS特化の細かな制御は難しそうにみえていて、マルチクラウドでなければあえて選ぶ必要性を感じなかった。


## HashiCorp Waypoint

Terraform大好きな自分としてはHCLで書くことのできるWaypointはとても好感触だったが、現在(2021-04-18)時点ではLambdaの場合はImageのみ対応で、Zipにも対応しておらず、かつ周辺のリソースについても制御はできないため、プロダクション利用で進めていくには時期尚早と感じた。

たとえばAPI Gatewayを利用したデプロイはWayPointではできず、OCI Image at Lambda with ALB の構成しか組めない。
Lambdaをいい感じに使うツールというものではなさそうだ。


## apex/up

数年前であれば、Lambdaの管理と言えばapexと印象がありましたが、今はアーカイブされた
どうも有償化して、OSSの機能を絞っているような印象を受けた。
コードの更新も半年近く止まっているので、今から選択するツールではなさそう。


[https://apex.sh/up/:embed:cite]
