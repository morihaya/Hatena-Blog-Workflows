## Jenkinsfileでcron定期実行指定

[v2](https://jenkins.io/2.0/)になってから[久しい](https://jenkins.io/changelog-old/)[^1]Jenkinsですが、Jenkinsfileによるジョブのコード化がとても良いです。

小ネタでJenkinsfileでのcron実行の方法を調べたのでメモです。

[Documentのcron-syntax](https://jenkins.io/doc/book/pipeline/syntax/#cron-syntax)に書いてある通りなのですが、以下のようにcronでかけます。


```groovy
Jenkinsfile (Declarative Pipeline)
pipeline {
    agent any
    triggers {
        cron('H */4 * * 1-5')   <-ここ
    }
    stages {
        stage('Example') {
            steps {
                echo 'Hello World'
            }
        }
    }
}
```

ここで面白いのが `H` の部分。
これは標準のcronには無いパラメタで、乱数的な意味になります。具体的にはサンプルの例だと、分に `H` が指定あるため `00-59` のどこか、となります。

しかし注意点として、ドキュメントにも以下のように記載があり、乱数(random)では無いとのことです。ジョブ名からハッシュで数値が決定され、毎回変動するわけではありません。

>The H symbol can be thought of as a random value over a range, but it actually is a hash of the job name, not a random function, so that the value remains stable for any given project.

## おまけ
簡単だと思って追加したところ、以下のエラーが発生しました。
これは読んで字のごとくなのですが、trigger句が複数回出ているぞ！というエラーです。

>WorkflowScript: 23: Multiple occurrences of the triggers section @ line 23, column 5.


というのもサンプルを見てagent anyの下に以下を追加したのですが

```groovy
   ...略...
    agent any
    triggers {
       cron('H 22 * * *')
    }
   ...略...
```

実はJenkinsfileの下の方にGitLab連携用にtriggersが記載されており、重複していたというお粗末な理由でした。これはサンプルをそのまま使うとありそうな内容なので、自戒として記載しておきます。

```groovy
    triggers {
        cron('H 22 * * *')   <-ここに追加するのが正しかった
        gitlab(
            triggerOnPush: true,
            triggerOnMergeRequest: true,
            branchFilterType: 'All',
            addNoteOnMergeRequest: true,
            addCiMessage: true
        )
    }
```
